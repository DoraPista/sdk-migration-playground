# Setup Details

Everything you might need beyond [Start here](../README.md#start-here).

## Requirements

- **.NET 10 SDK.** `global.json` pins the major version; `dotnet --version` should report 10.x.
- **For the MAUI app** (12-01 to 12-03): `dotnet workload install maui-windows`. See
  [exercises/12-maui/README.md](../exercises/12-maui/README.md).
- **Optional:** the .NET Framework 4.8 sample host in 09-04 (`samples\LegacyHost`) needs the .NET Framework 4.8
  targeting pack.

## Building everything

```powershell
dotnet build InterviewGym.slnx
```

The first build restores packages and takes a few minutes; do it before a timed session. `InterviewGym.slnx`
contains every project except the MAUI app, and opens in recent versions of Visual Studio and Rider.

## The mock platform

Several exercises talk to a local HTTP server that behaves like the real platform (OAuth2, chunked uploads,
long-running operations, rate limits) and can be told to fail in specific ways. Tests that need it start it
themselves, so you rarely have to. To run it on its own:

```powershell
.\gym server                                               # or:
dotnet run --project shared/MockServer/Gym.MockServer      # http://localhost:5080
```

Its contract, including the control endpoints used to inject failures, is in
[shared/MockServer/API.md](../shared/MockServer/API.md).

## Mock data

`shared/MockData` holds a normal dataset, a `large` one (5,000 files, 150 projects), a `malformed` one, and real
sample files, including a zero-byte file, Unicode names, one corrupted file and one that is referenced but missing.
It is regenerated byte-for-byte with:

```powershell
dotnet run shared/MockData/tools/GenerateMockData.cs -- shared/MockData
```

## Resetting an exercise

`.\gym reset <id>` restores an exercise from Git after showing you what will be discarded. Without the gym command:
`git checkout -- exercises/<category>/<exercise>`. Working on an exercise only changes its own folder, except the
MAUI app exercises, whose code lives in `exercises\12-maui\MauiGym` (`gym reset` knows which files belong to which).

## The gym's own files

The gym keeps two things in a `.gym\` folder in the repository, which Git ignores: `state.json` (the exercises
you have done, and the editor you chose) and `solutions\` (a small solution per exercise, created when you open one
in Visual Studio or Rider). Delete the folder to start your progress again. To pick a different editor:
`.\gym open <id> --choose`.

## Path length, line endings, ZIP downloads

- **Keep the path reasonably short.** Build output reaches about 160 characters below the repository root, and
  Windows enforces a 260-character limit unless long paths are enabled. `C:\dev\dotnet-interview-gym` is fine; a
  deeply nested OneDrive folder may not be. To lift the limit (admin, then reboot):
  `reg add HKLM\SYSTEM\CurrentControlSet\Control\FileSystem /v LongPathsEnabled /t REG_DWORD /d 1 /f`
- **Keep `.gitattributes`.** `shared/MockData` holds real file content whose SHA-256 hashes and sizes are recorded
  in `files.json` and checked by the tests. Without `.gitattributes`, Git would convert line endings on checkout
  and break several exercises for reasons unrelated to the exercise.
- **ZIP downloads** may be marked as blocked. Clear that before building: `Get-ChildItem -Recurse | Unblock-File`

## Handing the repository to someone else

To give someone a copy without the answers, uncomment the `/interviewer/` line in `.gitignore`, or run
`interviewer\tools\make-candidate-copy.ps1 -Destination <folder>`, which copies the repository without them.

## For interviewers: checking the solutions

`interviewer\tools\verify-solutions.ps1` copies the repository to a scratch folder, applies every solution and runs
the tests (all should pass). With `-Baseline` it runs the untouched exercises instead (most should fail).
